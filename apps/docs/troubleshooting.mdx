## Session & Authentication

<AccordionGroup>
  <Accordion title="Session expired">
    Your session token has a limited lifetime. When it expires, re-authenticate:

    ```bash
    relic login
    ```

    <Tip>
      Session data is stored at `~/.config/relic/session.json` (`%APPDATA%\relic\session.json` on Windows). If the file is corrupted, delete it and log in again.
    </Tip>

  </Accordion>

  <Accordion title="Invalid JWT error">
    JWT tokens refresh automatically. If the error persists, clear your session and re-authenticate:

    ```bash
    relic logout
    relic login
    ```

  </Accordion>
</AccordionGroup>

## Secret Injection

<AccordionGroup>
  <Accordion title="relic run says Server Error or Environment not found">
    If `relic run -e <name>` prints `Server Error` or `Environment not found`, the environment name is missing or wrong.

    1. Run `relic` and open your project.
    2. Create an environment (for example `development`), or copy the exact name you already have.
    3. Run again: `relic run -e development -- <command>`

    `relic init` alone does not create environments. Create at least one environment before `relic run`.

  </Accordion>

  <Accordion title="relic run returns no secrets">
    Check the following:

    1. Verify the environment name matches exactly: `relic run -e development -- ...`
    2. Make sure `relic.toml` exists in your project root (run `relic init` if not)
    3. Clear stale cache:

    ```bash
    rm .relic/cache.db
    ```

    The next `relic run` will fetch fresh data from the server.

  </Accordion>

  <Accordion title="Secrets have outdated values">
    Cache invalidation happens automatically when secrets are updated. If you still see old values, delete the local cache:

    ```bash
    rm .relic/cache.db
    ```

    <Note>
      When using API keys (CI/CD mode), caching is disabled and secrets are always fetched fresh.
    </Note>

  </Accordion>
</AccordionGroup>

## TUI

<AccordionGroup>
  <Accordion title="Colors or UI elements look broken">
    Relic's TUI requires a terminal with true color support. Use one of these:

    - [Ghostty](https://ghostty.org)
    - [Alacritty](https://alacritty.org)
    - [Kitty](https://sw.kovidgoyal.net/kitty)
    - [WezTerm](https://wezfurlong.org/wezterm)

    You can verify your terminal supports true color:

    ```bash
    echo $TERM
    ```

    <Tip>
      If you see `xterm` or `screen`, your terminal may not support the full color range the TUI needs.
    </Tip>

  </Accordion>

  <Accordion title="TUI won't start or crashes">
    Run with debug logging enabled to see what's happening:

    ```bash
    RELIC_LOG=debug relic
    ```

    Then check the log file:

    ```bash
    cat ~/.config/relic/logs/debug.log
    ```

  </Accordion>
</AccordionGroup>

## Debugging

When something isn't working, enable debug logs to get more information.

<Steps>
  <Step title="Enable debug logging">
    Set the `RELIC_LOG` environment variable:

    ```bash
    RELIC_LOG=debug relic run -e development -- npm start
    ```

  </Step>
  <Step title="Check the log file">
    Logs are written to `~/.config/relic/logs/` (`%APPDATA%\relic\logs\` on Windows):

    | Mode | File |
    |------|------|
    | Development | `debug.log` |
    | Production | `relic.log` |

    Override the log path with `RELIC_LOG_FILE` if needed.

  </Step>
  <Step title="Watch logs in real time">
    Tail the log file while running Relic in another terminal:

    ```bash
    tail -f ~/.config/relic/logs/debug.log
    ```

  </Step>
</Steps>

## Windows

Windows support is in beta. These are the differences you are most likely to run into.

<AccordionGroup>
  <Accordion title="'relic' is not recognized after installing">
    The PowerShell installer adds `%USERPROFILE%\.relic\bin` to your user `PATH`, but terminals that were already open keep the old value. Open a new terminal window, or update the current session:

    ```powershell
    $env:Path = "$env:USERPROFILE\.relic\bin;$env:Path"
    ```

  </Accordion>

  <Accordion title="Running scripts is disabled on this system">
    Your execution policy blocks the installer. Run it with the policy bypassed for that one process:

    ```powershell
    powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://withrelic.com/install.ps1 | iex"
    ```

  </Accordion>

  <Accordion title="relic run cannot find my command">
    The runner looks up commands in `PATH` using the extensions in `PATHEXT`, limited to `.com`, `.exe`, `.bat`, and `.cmd`. The current directory is not searched.

    - For a script in the current directory, use a path: `relic run -e dev -- .\build.cmd`
    - For `cmd.exe` built-ins such as `echo` or `set`, go through the shell. From PowerShell: `relic run -e dev -- cmd /c echo %API_URL%`
    - For PowerShell scripts, call PowerShell: `relic run -e dev -- pwsh -File .\deploy.ps1`

    The child process only inherits a fixed set of system variables. See the [runner environment allowlist](/development/runner#environment-allowlist). If your tool needs another variable from your shell, store it as a Relic secret.

  </Accordion>

  <Accordion title="relic upgrade prints a command instead of upgrading">
    Windows does not allow a running `relic.exe` to be replaced. If you installed with npm, Bun, or Scoop, `relic upgrade` prints the command to run once it exits, for example:

    ```powershell
    npm install -g relic@latest
    ```

    Installs from the PowerShell installer upgrade in place: the installer moves the running binary aside to `relic.exe.old` and removes it on the next install.

  </Accordion>

  <Accordion title="TUI colors or layout look wrong">
    Use [Windows Terminal](https://aka.ms/terminal), which is the default terminal on Windows 11. The legacy console host (`conhost.exe`) on older Windows 10 builds may render colors and box characters incorrectly.
  </Accordion>

  <Accordion title="Enable debug logs in PowerShell">
    PowerShell sets environment variables differently from Unix shells:

    ```powershell
    $env:RELIC_LOG = "debug"
    relic run -e development -- npm start
    Get-Content -Wait "$env:APPDATA\relic\logs\relic.log"
    ```

  </Accordion>
</AccordionGroup>

## Cache

Relic caches data locally to reduce API calls. If you need to reset it:

| What to clear    | How                                                |
| ---------------- | -------------------------------------------------- |
| Project cache    | Delete `.relic/cache.db` in your project directory |
| User key cache   | Delete `~/.config/relic/relic.db` (`%APPDATA%\relic\relic.db` on Windows) |
| Session and auth | Run `relic logout`                                 |

<Warning>
  Clearing the user key cache does not delete your encryption keys from the server. You will not
  lose access to your secrets.
</Warning>

## What never to paste (Discord / GitHub / DMs)

Hygiene only — no crypto claims. Secret **names** are OK. Secret **values** are never OK — including in screenshots, screen recordings, and “redacted” snippets that still show part of a token.

**Never paste (or show on camera):**

- Secret values, API tokens, JWTs, cookies, Authorization headers, private keys / PEM blocks, master passwords
- Full `.env` bodies or any `RELIC_*` / Wrapper credential values
- Wrapper share codes, attach links, or session URLs (anyone with the link can reach the shared session)
- Device-auth / OIDC one-time codes, login callback URLs, or magic links
- PTY dumps, agent transcripts, MCP tool output, or CI logs that contain values
- Request IDs that embed account data (when in doubt, omit)

**OK to paste:**

- OS + Relic / Wrapper version (`relic --version`)
- Exact command with environment **name** only (for example `-e development`)
- Error text / exit code with values removed
- Secret **names** only (for example `OPENAI_API_KEY` exists / missing)

**If you already pasted a value:** treat it as compromised — rotate that secret, revoke the share/session if applicable, then continue support with names-only evidence.

> Names yes. Values never. No `.env` dumps. No tokens. No share links. No PTY pastes. Screenshots count.
