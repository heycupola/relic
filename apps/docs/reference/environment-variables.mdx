title: Environment Variables
description: All environment variables that configure Relic's behavior.
---

Relic reads the following environment variables. None of them are required for normal usage.

## Authentication

| Variable              | Description                                                                                                                                                         | Default                            |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| `RELIC_SERVICE_TOKEN` | Service account token for CI/CD. Handles both authentication and decryption. Recommended over API keys.                                                             | None                               |
| `RELIC_OIDC_TOKEN`    | OIDC token for identity verification. Requested automatically in GitHub Actions. In GitLab CI, define it with `id_tokens` (see [OIDC](/guides/oidc#gitlab-ci)).     | Auto-detected in GitHub Actions    |
| `RELIC_PASSWORD`      | Master password for secret decryption. Used with `RELIC_API_KEY` in CI/CD (deprecated).                                                                             | Read from keychain or file         |
| `RELIC_API_KEY`       | API key for CI/CD authentication (deprecated). Use `RELIC_SERVICE_TOKEN` instead.                                                                                   | None                               |
| `RELIC_PROJECT_ID`    | Project ID. Overrides `relic.toml`; the `--project` flag overrides this variable.                                                                                    | Read from `relic.toml`             |

`relic run` (on macOS and Linux) and the MCP server don't pass `RELIC_*` variables from your environment to the command they run.

## Platform Sync

Used by [`relic push`](/guides/platform-sync). Each one is optional when you're logged in with the platform's own CLI.

| Variable                | Description                                                                                                  | Default                                  |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------- |
| `VERCEL_TOKEN`          | Vercel access token for `--target vercel`.                                                                   | Read from the Vercel CLI `auth.json`     |
| `CLOUDFLARE_API_TOKEN`  | Cloudflare API token with Workers Scripts: Edit. Used by wrangler, or by Relic directly when wrangler is not installed. | Your `wrangler login` session            |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare account ID, required with `CLOUDFLARE_API_TOKEN` when wrangler is not installed.                  | `account_id` from your wrangler config   |
| `GH_TOKEN`              | GitHub token read by the GitHub CLI for `--target github`.                                                   | Your `gh auth login` session             |
| `FLY_API_TOKEN`         | Fly.io token read by flyctl for `--target fly`.                                                              | Your `fly auth login` session            |

## Server

| Variable                | Description                                                          | Default                   |
| ----------------------- | -------------------------------------------------------------------- | ------------------------- |
| `RELIC_CONVEX_URL`      | Convex backend URL. Only needed for self-hosted or development.      | Production URL (built-in) |
| `RELIC_CONVEX_SITE_URL` | Convex HTTP actions URL. Only needed for self-hosted or development. | Production URL (built-in) |
| `RELIC_SITE_URL`        | Web dashboard URL. Only needed for self-hosted or development.       | Production URL (built-in) |

<Note>
  You do not need to set these when using Relic's hosted service. Earlier versions read
  `CONVEX_URL`, `CONVEX_SITE_URL`, and `SITE_URL`; those generic names are no longer read, so a
  `.env` file in your own project can't redirect the CLI to another server.
</Note>

## Logging

| Variable         | Description                                        | Default                                                                       |
| ---------------- | -------------------------------------------------- | ----------------------------------------------------------------------------- |
| `RELIC_LOG`      | Log level: `debug`, `info`, `warn`, `error`, `off` | Dev: `info`, Prod: `warn`                                                     |
| `RELIC_LOG_FILE` | Override log file path.                            | Dev: `~/.config/relic/logs/debug.log`, Prod: `~/.config/relic/logs/relic.log` |

## Telemetry

| Variable              | Description                                      | Default                      |
| --------------------- | ------------------------------------------------ | ---------------------------- |
| `RELIC_TELEMETRY`     | Set to `false` to disable telemetry.             | Enabled                      |
| `RELIC_POSTHOG_KEY`   | PostHog API key. Telemetry is disabled if empty. | Empty                        |
| `RELIC_TELEMETRY_URL` | PostHog proxy host.                              | `https://telemetry.withrelic.com` |

## Installation

| Variable            | Description                                                                                         | Default    |
| ------------------- | --------------------------------------------------------------------------------------------------- | ---------- |
| `RELIC_INSTALL_DIR` | Install location for the `curl` install script. `relic upgrade` reuses the running binary's folder. | `~/.relic` |

## Importing

Read by [`relic import vercel`](/guides/importing#vercel). Flags take precedence over these variables.

| Variable            | Description                                                         | Default                               |
| ------------------- | ------------------------------------------------------------------- | ------------------------------------- |
| `VERCEL_TOKEN`      | Vercel access token used to read project environment variables.     | Token from `vercel login`             |
| `VERCEL_PROJECT_ID` | Vercel project ID or name. Overridden by `--vercel-project`.        | Read from `.vercel/project.json`      |
| `VERCEL_ORG_ID`     | Vercel team ID. Overridden by `--vercel-team`.                      | Read from `.vercel/project.json`      |

## Runtime

| Variable | Description                                                                                                                                   | Default |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| `DEV`    | Set to `true` to enable development mode. Switches server URLs to localhost, enables console logging, debug log file, and disables telemetry. | Not set |
| `CI`     | When set (any value), disables telemetry and console logging. Detected automatically by most CI providers.                                    | Not set |

## Set by `relic shell`

[`relic shell`](/guides/local-development) sets these inside the subshell. You don't set them yourself.

| Variable            | Description                                                                         |
| ------------------- | ----------------------------------------------------------------------------------- |
| `RELIC_SHELL`       | `1` inside a relic shell. Used to refuse nested shells unless `--force` is passed.  |
| `RELIC_ENVIRONMENT` | Environment name of the active shell.                                               |
| `RELIC_PROJECT_ID`  | Project ID of the active shell. Not set when using a service token.                 |
| `RELIC_FOLDER`      | Folder passed with `-f`, if any.                                                    |
| `RELIC_SCOPE`       | Scope passed with `-s`, if any.                                                     |

## CI/CD Quick Reference

The recommended way to run Relic in a CI/CD pipeline using a service account:

```bash
RELIC_SERVICE_TOKEN=rsk_...   # Service token from `relic service-account create`
```

```bash
relic run -e production -- npm run deploy
```

<Tip>Service accounts are scoped to a project, so `RELIC_PROJECT_ID` is not needed.</Tip>
